# release/extras/

Anything committed in this folder ships with the next release.

`build-releases.sh` copies these files into `release/APGO/` (step 5b) **before**
the torrent is hashed, so an extra is treated exactly like a built installer: it
goes into the torrent, into `manifest.txt`, up to the package registry, and out
to the website at `/downloads/APGO/<file>`. Nothing downstream is hardcoded —
adding a file here is the whole change.

## What belongs here

Small, hand-maintained things that can't be produced by a compiler:

- `RELEASE-NOTES.md` — what changed in this version
- `SHA256SUMS` — checksums you generated and signed
- `SHA256SUMS.asc` — the detached signature
- `client.yaml.sample` — a starting config for people who grabbed the torrent

## What does not belong here

- **Build output.** Installers are produced by the script into `release/APGO/`
  and are gitignored. Committing a binary here puts it in git history forever,
  which is exactly what the website split was done to avoid.
- **Subdirectories.** The payload is a flat folder (the torrent's content root),
  so nested directories are skipped with a warning.
- **Anything named like a built artifact.** On a name collision the freshly
  built file wins and your extra is skipped with a warning — shipping a stale
  committed copy over a real build would be a bad way to release the wrong
  binary.

Dotfiles (`.gitkeep` and friends) are never shipped.
